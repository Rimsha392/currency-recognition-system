RECOMMENDATION: Merge '<denom>_front' and '<denom>_back' into a single
'<denom>' class for training (e.g. '500_front' + '500_back' -> '500').

Reasoning:
  1. The task is denomination recognition, not side recognition --
     merging aligns the label space with the actual product goal.
  2. It doubles effective samples per class with zero new data collection,
     which matters given how small each per-side folder is.
  3. Denomination-specific visual cues (color, size, printed number,
     security features) are shared across front/back and are exactly
     what transfer-learned CNN features are good at picking up on,
     even amid the artwork differences between sides.
  4. Only keep front/back separate if a future feature explicitly
     requires knowing which side is shown -- out of scope for this MVP.
